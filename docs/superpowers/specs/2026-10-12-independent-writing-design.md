# 瑞安漂流日记：独立写作流程改造方案

日期：2026-10-12

状态：已被 2026-10-12 后续用户决定替代。用户选择 Maggie 的视觉方向及文件写作方式，主流程改为 OneNote 收集、VS Code 编辑 Markdown/MDX、本地预览、脚本发布。下文保留为先前提案，不再指导本次实施；当前流程见 ../../writing-guide.md。尚未推送上线。

## 已明确的要求

- 网站名称为「瑞安漂流日记」。
- 主要在电脑上写作，手机需要能够通过网页上传照片和文件。
- 日常写作与发布必须能由作者独立完成，不依赖每次找 AI 整理。
- 保留现有 Astro、Markdown 和 GitHub Pages 基础；视觉风格仍在比较参考博客。

## 三种方式与建议

1. 网页后台为主（推荐）：打开写作台，直接写作或粘贴正文，插入照片，保存草稿，检查预览，发布。电脑和手机使用同一个后台。
2. 本地 Markdown 为主：文件归自己管理，离线方便，但需要编辑器和同步流程。保留为可选入口，不要求作者学习 Git 才能发文。
3. AI 协助导入：仅用于旧文批量迁移、复杂 Word/PDF 提取与格式清理。它是补充能力，不是发布的前置条件。

## 推荐的日常流程

作者打开 `/admin/` → 登录 → 新建文章 → 填标题、日期、栏目、标签 → 写作或粘贴正文 → 插入照片 → 保存草稿 → 在后台检查内容预览 → 主动发布 → 查看构建状态与文章页面。

没有格式复杂的导入材料时，全程由作者自己完成。Word/PDF 的文件上传先按附件处理，不承诺上传即自动生成排版完善的文章。普通文章可直接复制文字到编辑器，配图单独上传。

## 改造内容

### 可发布的基础

- 恢复并核验缺失的文章配置、链接工具、RSS 与图标文件，使本地构建通过。
- 保持已有文章地址稳定，并统一日期解析。
- 修复主题筛选，使作者设置的标签确实能用于浏览。

### 登录和编辑

- 保留现有 Sveltia CMS，优先接好 GitHub OAuth 登录。当前项目有认证 Worker 源码，但 CMS 配置未指定认证服务地址；需要核实已部署服务及 OAuth 回调信息。
- 中文字段包括标题、摘要、发布日期、更新日期、栏目、标签、正文。
- 保留现成富文本编辑器和 Markdown 输入方式，支持选择照片、插入图片、上传附件。
- 后台内容预览用于检查文字和图片；它与正式页面预览不同。第一版不额外搭建公开的草稿预览站。

### 草稿和发布

- 使用后台原生的草稿与发布流程作为作者的主要操作入口。
- 理顺原生工作流状态与文章 `draft` 字段的关系，避免作者点击发布后仍因另一个开关无法显示。
- 处理任何既有 `draft: true` 文章前，核查其公开意图；不能为了消除冲突批量改成公开。
- 未发布文章不得进入公开文章页、列表、RSS 和站点地图。
- GitHub 若使用公开仓库，分支中的草稿源码也可能公开；后台草稿不是私人笔记仓库。`public/` 中的图片和附件不因文章处于草稿状态而自动私密。
- 发布结果以 GitHub Actions 成功和正式文章可访问为准。构建失败时显示或提供可查的状态入口，不把点击按钮当作上线成功。

### 图片和空间

- 照片原件保留在原有相册或网盘，网站上传适合阅读的副本。
- 目标为单张约 200–500 KB；是否能自动压缩，需要按项目锁定的 CMS 版本核实并实测，不预先声称已实现。
- GitHub Pages 的正式网站总大小上限为 1 GB，月流量软限制为 100 GB。仓库容量、网站容量与流量是不同指标。
- 不要求第一版引入额外图床；若实际图片积累接近容量上限，再评估。

## 验收

- 作者可独立完成新建、保存、再次打开、上传照片、预览和发布，不需要 AI 逐篇处理。
- 手机上可从相册或文件选择器选取素材，编辑器和按钮可正常使用。
- 一篇草稿经构建后不出现在任何公开索引或文章路由中。
- 一篇获准公开的真实文章可完成发布，文字、图片和链接正确。
- 标题修改不会无意改变既有文章地址。
- 新旧文章均能按日期和主题找到。
- README 包含准确的登录、写作、图片、发布状态、备份与故障处理说明。
